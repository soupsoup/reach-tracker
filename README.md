# reach-tracker
A public dashboard of source-backed article distribution. No fabricated counts, audience multipliers or estimated readership.

## Collection
`python3 scripts/collect.py` collects bounded exact-URL Bluesky and Hacker News results and checks known public source pages. Failures are stored explicitly. Public counters remain separate by platform. X, LinkedIn, Facebook and Reddit lack configured reliable collectors; NYT analytics are private. Syndication is verified through attribution evidence, not same-topic coverage. Search-index evidence and verification dates are retained separately from fresh direct checks.

GitHub Actions runs at `17,47 * * * *` (UTC), and supports manual dispatch. Scheduled runs may be delayed by GitHub. Snapshots are committed with contents-write permission; Git history preserves provenance. Every run writes an immutable timestamped snapshot. The dashboard serves up to 336 recent collections, fetching latest JSON directly from the public repository, so bot commits do not require Vercel rebuilds. All full snapshots remain available in the repository.

## Add articles and sources
Add an object with a unique id, title, publisher, published date, URL and sources to `data/articles.json`. The dashboard URL form registers articles automatically. New source records should begin as candidates unless independently verified; provide the evidence and verification date. Exact link discovery automatically promotes candidates with a direct backlink to citation. Same headlines alone never establish attribution. Known-source checks are partial discovery, not an exhaustive backlink index.

## Run and deploy
The home page starts with an empty URL form. Submitting any public HTTP(S) article URL saves a public registration in the project’s Vercel Blob store. A URL-encoded `?url=` share link opens that article directly, without sign-in. On-demand Bluesky and Hacker News checks populate new pages immediately; GitHub collection imports the public registry every run and persists scheduled snapshots. Existing articles retain their source ledger and history. No arbitrary article website is fetched by the on-demand service. Vercel serves the page and Node serverless registration/search endpoints; install dependencies with `npm ci`. `python3 -m unittest discover -s tests` verifies canonical matching and prevents headline-only and other-article social matches. No secrets are needed by collection. Refresh status distinguishes repository data from a deployment fallback. Unavailable counters are null, not zero. Historical snapshots preserve counters, source status and failures; the dashboard summarizes source and post changes.

## Sharing and persistence
Use **Track URL**, then **Copy link** to share the exact article tracking page. The registry is capped at 100 unique URLs. Shared pages load GitHub snapshots when available and fall back to live public checks for new URLs. Functional URL query parameters are retained; tracking parameters are removed. Publisher metadata not independently fetched is shown as the URL and hostname. No title, date or reach number is invented. Blob credentials are deployment secrets, never committed or sent to the browser. The GitHub collector uses the public `/api/registry` endpoint and does not need new credentials.

## Observed LinkedIn shares
Article pages include Google/Bing search shortcuts for indexed posts and a full LinkedIn post URL submission form. Submissions are public, saved in Blob (maximum 20 per article), and checked on page load, on demand, and during scheduled snapshot collection. Search is user-driven; no automatic search API is configured. A search result or user submission alone never enters verified share counts. The verifier requires SocialMediaPosting structured data identifying the requested post and linking the exact article. Only that post's explicit structured interaction counters are accepted; unavailable values stay null. Public request failures, login walls, redirects, shortened links and related posts remain candidates. Requests do not sign in or bypass access restrictions. Total network-wide shares remain unavailable.

## Connect X
1. Create a developer project/app in https://developer.x.com/ and obtain its Bearer Token with recent-search access. The API uses credits; set your spending limit in the X Developer Console before enabling.
2. In this repository's Settings → Secrets and variables → Actions → Secrets, add `X_BEARER_TOKEN`.
3. In Actions → Variables, add `X_COLLECTION_ENABLED` = `true`. Optional: `X_MONTHLY_REQUEST_LIMIT` (0–1500; default 1500 requests per UTC calendar month across all articles). This request cap is not a dollar budget; X's billing limit controls spend.
4. Run **Collect public reach** manually from the Actions tab, or wait for the next scheduled run.

The token stays in GitHub Actions and is never needed in Vercel or the browser. Collection makes one recent-search request per article per run, with at most 10 posts and no pagination. One article means 48 scheduled searches/day and up to 480 returned post records/day, plus manual runs. The collector verifies expanded/unwound link entities against the exact article URL, preserves missing metrics as null, and records authentication, billing and rate-limit failures. Native reposts are excluded as duplicate posts; original posts retain their repost/quote counters. Public data includes source URLs, authors and counters, not tokens or private analytics. Posts older than seven days will age out of the current observation; previous snapshots preserve historical observations. New URLs show X pending until their scheduled collection. `data/x-usage.json` records request attempts against the UTC-month cap.
